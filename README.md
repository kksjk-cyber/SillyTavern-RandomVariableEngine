# Random Variable Engine 1.3.2 · 事件记录版

合并 V1.1（诊断与兼容）、V1.2（概率）、V1.3（NPC档案）的升级版。适用于普通虚构剧情，延续 V1.0 的八类变数和双随机池，不包含原预设色情基调、内容限制绕过或强制内部思维链。不修改原预设、世界书或聊天记录。不是原预设的逐字复刻。


## V1.3.2 本轮事件卡
- 默认显示本轮事件卡：正文下方显示程序计算项数、模型报告采用项数、每项变数、参与者、结果及采用状态。点击展开查看判定依据、随机池取位、d100、概率修正，以及模型提供且能在正文中精确匹配的证据。关闭「隐藏点数提示」可查看点数。正文保留，不要求模型输出内部思维。
- 每轮生成结束时绑定本地计算结果到当前聊天的消息及前缀指纹；最近120条记录存在当前 WebView localStorage。无模型标签仍可显示已计算的记录；无判定也显示提示。未报告采用不等于未发生；报告及原文匹配也不等于语义验证。旧回复无法追溯丢失的计算记录，不伪造。编辑历史后旧记录可能不再匹配。未支持宿主生成结束事件、消息时序不匹配或存储不可用时，不猜测绑定，查看诊断日志与面板计算记录。
- 安装包包含新增 ledger.js 和 ledger.test.mjs，全部覆盖。面板「显示本轮事件卡」默认开启、「默认展开判定详情」默认关闭；启用「正文独立卡片」。如果旧版配置已关闭卡片，请手动开启。使用「填入测试队列」测试一次普通剧情；AI 自动识别关闭时仅使用手动队列。仍需在实际安卓 APK 验证。

## OPPO Pad / 安卓 APK 更新
1. 在 V1.0 的扩展面板记录配置；如果没有安装 V1.0，可直接安装本版。
2. 若已将 V1.0 上传到 GitHub，解压本包，把内部文件上传至同一仓库根目录（manifest.json 与 index.js 同级），同名文件覆盖。不要上传 ZIP、密钥、私有资料。若尚未建仓库，可新建公开仓库并上传。
3. 酒馆扩展管理中更新该扩展并刷新。如 APK 无更新按钮，先停用/卸载旧扩展，再用仓库 Git URL 安装。不要清除 APK 数据。禁止两版同时启用；二者使用同一个配置及注入 ID。
4. 本包未自动发布至 GitHub。若仓库名为 kksjk-cyber/SillyTavern-RandomVariableEngine，安装地址为 https://github.com/kksjk-cyber/SillyTavern-RandomVariableEngine.git （以实际仓库为准）。
5. 标准 ST 可复制到 data/<user-handle>/extensions/ 后重启。安卓封装可能缺少官方 API。

## 首次验证（无需额外付费请求）
- 在普通剧情中使用不含原随机规则的预设，关闭旧悬浮脚本和重复正则。打开扩展面板「随机变数引擎 1.3」。保持总开关和自动种子开启，AI 自动识别先关闭。
- 点「本地自检」：看到原版三类示例判定。点「填入测试队列」并发送与示例一致的普通剧情，例如“我遇到陌生制图师，试着打开之前发现的未解读航图盒”。生成结束后队列清空。
- 看顶部拦截/提交/宿主确认计数，以及诊断日志、实际注入文本。拦截=0 表示生成回调未触发；提交=0 表示未调用注入；提交>0而确认=0可能是APK没有公开预览事件、上下文预算/顺序问题，不能单凭此判断失败。确认表示宿主构建的提示词含本轮唯一标记，不证明远端模型收到或遵守。
- 如需自动判断，开启 AI 自动识别。额外一次 generateRaw 请求复用当前酒馆连接，可能收费。没有事件或模型分类失败时允许空判定。当前面板状态与日志不是网络请求抓包。

## V1.2 动态概率
默认关闭，以保留原版行为。开启后仅战斗、未知、策略三类使用独立 d100；其余仍采用原版五档/身份/人格/初见规则。保持十位池原本取位消耗不变；d100 额外独立抽取，不依赖十位种子、数字开关或固定复现。重新生成时可能重新抽取 d100。默认基础50%，各修正取 -30 至 +30，最终概率限制5–95%。判定为 d100 <= 阈值时成功；按差值分为大成功、成功、部分成功、部分失败、失败、大失败。概率是游戏数值，非客观估计；修正来源由用户/分类模型提供，程序做数值限制而非事实验证。每轮最多1–12个候选（默认6）。高级手动队列示例：
```json
{"events":[{"type":"combat","actor":"林舟","side":"ally","basis":"与对手进行剑术比赛","probability":{"base":50,"skill":20,"environment":-10,"preparation":15,"opposition":-10}}]}
```
显示实际点数、阈值及结果，事件是否真正发生由正文决定。没有逐句实时演算、跨轮事件冷却和剧情调度功能。

## V1.3 NPC 档案与信息差
- NPC 记忆默认开启；初次为空。使用快速表单保存姓名、人格、目标、地点。高级 JSON 可编辑信任、戒备、压力（0–100）、关系。最多80个角色、150条事实。姓名唯一；不实现实体消歧。每轮最多匹配近期消息中出现姓名的6个 NPC；非出场角色不保证主动行动。
- 事实可设置公开/知情人。插件只在全部匹配的角色均知情时注入非公开事实；无匹配角色时只传公开事实。该机制是保守的数据过滤，不是模型权限隔离；无法清除原聊天或其他插件已泄露的信息。角色姓名匹配也不等于真实在场。
- 可选自动 NPC 更新（默认关闭）：主模型可输出结构化提案。仅在正常追加回复结束后检查包含人名的正文证据，允许有限增量，不自动修改秘密权限或既定人格。文本匹配并非语义证明；需要手动复核。模型可能不输出或输出无效格式。重生成、滑动、编辑、删除后提示核查，尚不支持自动回滚；默认关闭可避免此问题。状态存储在当前设备 WebView localStorage，按聊天 ID 隔离，清除 APP 数据可能丢失，可复制 JSON 手工备份。无聊天 ID 则不允许持久化。未实现独立 NPC 行动规划、主动世界演化或 SAG。

## 原版功能与局限
保留原版10位种子、双随机池、八类变数、100位置人格标签、可点击回复选项、场景状态、叙事辅助和预设基调。部分原预设冲突规则延续 V1.0 的解释：五档按两位一组；中位向下取整；补全使用原始种子前段再翻转。原预设某些样式、宏、HTML内嵌和强制模型行为未移植。及时类事件是生成前计算而非真正实时执行。面板显示输出结构化标记；V1.3.1 默认将完整、可识别的数据块从聊天正文的显示层移出，具体限制见下。
